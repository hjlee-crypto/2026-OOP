# 10주차 객체지향프로그래밍 실습 — 생성형 AI 활용

> **학습 주제:** 함수형 프로그래밍 · 제네릭 · Java와 Kotlin 비교
> 
> 
> **실습 방식:** Java 코드 분석 → 생성형 AI 활용 → 작성·실행 → 결과 검증 → 수정·재실행
> 
> **실습 자료:** `OOP_10주차_생성형AI_활용_실습_워크시트_개정.pptx`
>
## 1. 학습 목표

1. 함수형 인터페이스, 람다식, 메소드 참조와 Stream API를 코드에 적용한다.
2. 제네릭 클래스·메소드 및 컬렉션의 타입 안정성을 이해한다.
3. Java 은행 계좌 코드를 생성형 AI로 Kotlin으로 변환하고 두 언어의 차이를 설명한다.
4. AI가 생성·변환한 코드의 정확성을 직접 컴파일·실행·검증하고 수정 이력을 남긴다.

## 2. 실습 준비

- **Java:** JDK 17 이상 권장 (실습에서 `List.of()`, `Map.of()` 사용)
- **Kotlin:** Kotlin/JVM 개발·실행 환경 (IntelliJ IDEA 등)
- **생성형 AI:** ChatGPT, Gemini, Claude 등 사용 가능한 도구
- **개발 도구:** IntelliJ IDEA, Eclipse, VS Code 등
- Java는 각 실습의 `package` 선언과 폴더 경로를 일치시킨다.
- Kotlin 실습은 Java와 별도 프로젝트 또는 소스 루트에서 실행해도 된다.

## 3. 실습 순서

| 구분 | 실습 주제 | 학습·작성할 내용 |
| --- | --- | --- |
| 01 | 계좌 클래스 | 필드, 생성자, 접근 제어, 입금·출금 및 입력 검증 |
| 02 | 함수형 인터페이스와 람다식 | `InterestPolicy`, 이자 계산 람다식 |
| 03 | 메소드 참조 | `id -> System.out.println(id)`를 `System.out::println`으로 변환 |
| 04 | Stream API | `filter()` → `map()` → `forEach()`와 반복문 비교 |
| 05 | 제네릭 클래스 | `Box<T>` 구현, 잘못된 타입 입력 시 컴파일 오류 확인 |
| 06 | 제네릭 메소드·컬렉션 | `List<T>`, `Map<K,V>`로 계좌 데이터 관리 |
| 07-A | Java → Kotlin: 클래스·생성자 | 필드·생성자·getter를 프로퍼티로 변환 |
| 07-B | Java → Kotlin: 입금·출금 | 입력 검증과 예외 발생 조건 유지 |
| 07-C | Java → Kotlin: 상속·오버라이딩 | `extends`, `@Override` ↔ `open`, `override` |
| 07-D | Java → Kotlin: 인터페이스·람다 | `fun interface` 및 함수 타입 비교 |
| 07-E | Java → Kotlin: Stream·컬렉션 | Java Stream과 Kotlin 컬렉션 함수 비교 |
| 종합 1 | Java 은행 계좌 프로그램 | 람다·Stream·제네릭을 하나의 프로그램에 통합 |
| 종합 2 | Java → Kotlin 전체 변환 | Java 프로젝트를 Kotlin/JVM으로 변환·검증 |

**주의:** 워크시트의 실습 01~07과 01-A~07-E는 서로 연결된 학습·검증 활동입니다. 예제를 작성한 뒤 해당 AI 활용 활동까지 수행합니다.

## 4. 모든 실습의 공통 진행 방법

1. **개념 확인:** 워크시트의 코드와 학습 목표를 읽고 생성형 AI에 핵심 문법을 질문한다.
2. **코드 작성·변환:** 직접 작성한 코드 또는 제공된 Java 파일을 AI에 첨부하고 필요한 코드 작성·수정을 요청한다.
3. **AI 결과 검토:** 클래스, 메소드, 접근 제어, 타입, 예외 처리 및 요구사항 누락 여부를 확인한다.
4. **컴파일·실행:** 원본과 수정 코드의 실행 결과를 확인한다. 오류 발생 시 오류 메시지를 기록한다.
5. **수정·재실행:** AI의 설명을 참고하되 직접 코드를 수정하고 다시 실행한다.
6. **결과 기록:** 사용 도구, 질문, 코드 변경 사항, 실행 결과와 본인의 판단을 기록한다.

### 생성형 AI 공통 질문 예시

```
첨부한 Java 코드를 분석해 줘.
1. 클래스·필드·생성자·메소드의 역할을 설명해 줘.
2. 이번 실습의 핵심 문법이 적용된 부분을 찾아 줘.
3. 오류 또는 개선할 부분이 있다면 이유를 설명해 줘.
4. 수정한 전체 코드를 파일별로 작성해 줘.
5. 예상 실행 결과와 직접 검증할 테스트 입력을 제시해 줘.
```

### Java → Kotlin 변환 프롬프트

```
첨부한 Java 은행 계좌 프로그램을 Kotlin/JVM 코드로 변환해 줘.

1. 기존 클래스와 기능을 가능한 한 동일하게 유지해 줘.
2. Kotlin 파일별 전체 코드를 작성하고 파일명을 표시해 줘.
3. 생성자, val/var, private, open, override 변경 이유를 설명해 줘.
4. 입금·출금 검증과 예외 발생 조건이 유지되는지 확인해 줘.
5. 함수형 인터페이스·람다식과 Stream 코드를 Kotlin 방식으로 변환해 줘.
6. 실행 가능한 main 함수와 실행 방법을 제시해 줘.
7. Java와 Kotlin에 동일한 입력을 사용한 예상 결과를 비교해 줘.
```

> 생성형 AI가 작성한 코드는 정답으로 간주하지 않습니다. **반드시 직접 실행하고 결과를 확인**해야 합니다.
> 

## 5. 종합 실습: 은행 계좌 프로그램

다음 기능을 **하나의 Java 프로그램**으로 구현한 후, 생성형 AI를 이용해 Kotlin으로 변환합니다.

- `Account` 객체를 3개 이상 생성한다.
- `List<Account>`에 계좌를 저장한다.
- Stream `filter()`로 잔액 **100,000원 이상** 계좌를 조회한다.
- `InterestPolicy` 함수형 인터페이스와 람다식으로 이자를 계산한다.
- `Box<Account>`로 계좌 객체를 보관한다.
- 정상 입력과 오류 입력을 테스트한다.
- Java와 Kotlin의 **동일 입력·출력 결과**를 비교한다.

**제공 Java 예제:** `10w-java-bank-account.zip`에 포함된 `Account.java`, `InterestPolicy.java`, `Box.java`, `BankTest.java`를 참고할 수 있습니다. 이 종합 예제는 개별 `ex01`~`ex07` 실습 파일과 구분해서 관리합니다.

## 8. 학습 시 유의사항

- 생성형 AI를 활용해 전체 코드를 작성하거나 변환해도 됩니다.
- AI 사용 비율 자체는 감점 기준이 아닙니다.
- AI로 생성한 코드라도 **객체지향 설계, 코드 이해도, 실행 검증, 수정 능력**이 중요합니다.
- Kotlin 변환 시 문법만 바꾸지 말고 **캡슐화·상속·다형성·예외 처리의 의미가 유지되는지** 확인합니다.
- 최종 코드를 설명하거나 간단한 변경 요청에 대응할 수 있도록 학습합니다.
